# PhysicsLab repository guide

## Область проекта

- apps/web — учебная платформа PhysicsLab на Next.js.
- apps/game — отдельный Godot-продукт; его контекст: docs/game-preproduction/CONTEXT.md.
- PhysicsChannelKit и PhysicsChannelOutput — отдельный процесс подготовки материалов. Не переносить между этими областями продуктовые, учебные, визуальные или технические требования.

## Веб-продукт и источники

Для задач apps/web начни с docs/current/START_HERE.md, затем читай только документы и код по задаче. Инструкционная задача не требует чтения исходников, если код не нужен для проверки утверждения.
При разногласиях порядок такой: явная просьба пользователя → docs/current/ → решения CANON в docs/decisions/ → наблюдаемое поведение кода/CI → docs/archive/ и legacy/ как история. Конфликт docs/current с CANON сообщай явно. Архив не задаёт текущие требования.
Идентичность Мио задана в docs/current/MIO_CHARACTER.md. Не возрождай Nova/старые мотивы по архивным файлам. .agents/ содержит вспомогательные Skills и не меняет product direction. Не превращай один удачный урок или экран в общий шаблон без подтверждения; при изменении CANON обновляй связанный current-документ.

## Технические соглашения

Используй npm; CI отдельно устанавливает root package-lock.json и apps/web/package-lock.json. Обычные команды веб-приложения запускаются из корня. Не запускай Next build одновременно с dev-сервером, если они используют общий .next.
Sites/Vinext и design-sync — необязательные инструменты, не источники архитектуры или визуального направления. Не обновляй визуальные baseline только ради прохождения теста.

## Проверки и CI

Следуй docs/current/QUALITY.md и применимому Skill. Проверка — по риску, а не обязательный ритуал: браузер нужен при существенном визуальном, responsive, browser-only или interaction вопросе либо по просьбе пользователя. Связанные UI-изменения группируй; при необходимости делай один целевой просмотр изменённого экрана. После локальной правки не запускай полный test/E2E/visual/a11y suite или production build без конкретной причины.
В CI сначала смотри сводку job/step; полный лог читай только для конкретного неясного падения. Не перечитывай прежний лог и не опрашивай running workflow циклически.

## PhysicsLab tool policy

- docs/current/ и docs/current/QUALITY.md имеют приоритет над общими defaults Skills и plugins; QUALITY.md задаёт бюджет проверок.
- frontend-design — default для существенной работы с UI; отрисованный результат проверяй, когда задаче нужны rendered evidence.
- Внешние design, research и generation workflows подключай под конкретный пробел; не складывай перекрывающиеся workflows.
- Vendor/plugin files и cached skills не редактируй.
- Временные debugging learnings не записывай в AGENTS.md без моей прямой просьбы.
