# PhysicsLab

PhysicsLab — учебная платформа по школьной физике для белорусских школьников.
Веб-продукт объединяет связные объяснения, иллюстрированный учебник,
исследования и опыты, задачи, тесты, разбор ошибок и подготовку к ЦТ/ЦЭ.
Практика и экзаменационная диагностика — части продукта, а не весь продукт.
Текущее покрытие неполное; фактические границы реализации описаны в
`docs/current/PRODUCT.md`, а цель релиза — в `docs/current/RELEASE_GOAL.md`.

## С чего начинать работу

Если вы агент или новый разработчик, не выводите направление проекта из
случайных файлов, старых ассетов или количества совпадений в репозитории.
Порядок входа:

1. `AGENTS.md` — границы продуктов и порядок источников истины.
2. `docs/current/START_HERE.md` — короткая карта актуального состояния.
3. Нужные файлы из `docs/current/` и `docs/decisions/`.
4. Только затем — текущий код, тесты и рендер затронутого маршрута.

## Структура репозитория

- `apps/web` — текущий веб-продукт. Канонический runtime: Next.js 16 + React 19.
  Генератор задач находится в `apps/web/lib/server/task-generator`.
- `docs/current/` — действующая продуктовая, учебная, дизайнерская,
  архитектурная и quality-документация веб-продукта.
- `docs/decisions/` — зафиксированные `CANON`-решения.
- `docs/archive/` и `legacy/` — исторические материалы и прежние прототипы.
  Они не задают текущие требования.
- `apps/game` — отдельный Godot-продукт. Его контекст находится в
  `docs/game-preproduction/`; требования игры нельзя переносить в web без
  прямого запроса пользователя.
- `PhysicsChannelKit` и `PhysicsChannelOutput` — отдельный инструментарий и
  производственный архив для физико-математического контента/Telegram. Они не
  являются частью runtime `apps/web` и не задают требования PhysicsLab Web.
- `.design-sync/`, `.ds-*`, Vinext и `.vinext` — вспомогательные preview/deploy
  механизмы. Они не являются источником продуктового или визуального направления.
- `Новая папка/` — неканонический остаток старой работы. Не использовать его
  как источник требований; перед удалением или переносом сначала проверить,
  что на него нет активных ссылок.

## Установка

Нужны две установки — корень содержит Playwright/TypeScript и оркестрацию,
зависимости приложения живут в `apps/web`:

```bash
npm ci
npm ci --prefix apps/web
```

## Команды (из корня)

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер на :3000 |
| `npm run check` | TypeScript (`tsc --noEmit`) |
| `npm test` | все юнит-тесты |
| `npm run test:physics` | физика, диаграммы и генератор задач |
| `npm run test:e2e` | Playwright против dev runtime |
| `npm run test:a11y` | axe-проверки доступности |
| `npm run test:visual` | визуальные/layout-проверки |
| `npm run build` | production-сборка |
| `npm run preview` | `next start` поверх сборки |
| `npm run assert:routes` | проверка production-манифеста маршрутов |
| `npm run smoke` | production smoke на :3100 |
| `npm run verify` | стандартная локальная проверка завершённой scoped-задачи |
| `npm run verify:full` | интеграционная/PR-level проверка |

## Известные грабли

- Не запускайте `npm run build`, пока работает `npm run dev`: они делят
  `.next/`, и dev-сервер может начать сыпать `ENOENT _buildManifest`.
- По умолчанию Playwright поднимает собственный сервер на :3000 и откажется
  стартовать, если порт занят. Переиспользование уже запущенного сервера
  включается только явно через `PLAYWRIGHT_REUSE_SERVER=1`.
- `/dev/*` — только dev-витрины. В production эти маршруты отсутствуют.
- `npm run smoke` требует свежий `npm run build` и остановленный dev-сервер.
- Прогресс ученика хранится в браузере, но его можно экспортировать и
  восстановить через профиль; localStorage не является единственной копией.
